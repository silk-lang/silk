## Disposition after controlled four-core results

Root's matched V22→V2 controls reject the current package: cold check11.531→15.888s (+37.8%), CPU38.148→40.223s (+5.4%); cold build19.671→27.803s (+41.3%), CPU62.214→69.267s (+11.3%); second build edit+19.3%. CPU0 results were still running when this note was finalized. The following design is a parked feasible architecture, **not authorization to implement or a claimed rescue**. Donation and overlap can redistribute elapsed work but do not explain away increased total CPU or warm-source/interner costs. Root is prioritizing other structural lanes on the validated process baseline.

## Parked scheduler candidate

Use the existing four stores throughout; no extra threads, process forks or shared mutable Semantic/Query objects. Combine bounded runtime task donation with two-pass shutdown, while keeping V2 frozen for paired controls. Treat extension balancing as the same task engine's second phase, rather than introducing an unrelated scheduler.

1. **Quiescent dynamic queue.** Replace the ordinal-only `ThreadFrontier.TaskQueue.take` exhaustion condition with ready tasks plus an outstanding-task count. Outstanding includes queued and executing tasks. A donor enqueues children and increments outstanding before completing its task; finishing decrements it. Empty queue with outstanding>0 waits on a Condition, outside semantic/interner locks. Empty queue with outstanding0 ends the barrier. Cancellation wakes all waiters; a failed task cancels the entire round. Idle workers must remain in this loop, not publish a final packet and enter retained-command service while a runtime producer can still donate. Bounded full queues refuse donation and retain work locally. No allocator, payload destruction, provider invocation or waiting for a Body answer occurs under the queue lock.

2. **Donate only complete-MIR successors before their target claim.** The concrete seam is `Semantic.capturedEscapesTimed`: after a parent's MIR references/summary have been recorded, select pending `BackendVisit.Enter` items before `claimWorkerMir` and target MIR demand. Only the explicitly marked runtime-walk frame initially donates; nested cleanup/extension frames do not inherit permission accidentally. Prefer a small batch only when there are idle consumers and a real pending width (e.g.16); cap queue slots/retained seed bytes. `InstanceSeed.make` already copies all five canonical key variants and reconstructs private mutable wrappers with `instantiate`; it refuses excessive depth/provider lists. Donation refusal is a local-work fallback, never lost coverage.

3. **Portable visit versus local origin.** A native task carries InstanceSeed, Edge, source ModuleId/Span, cleanup Type and RelatedSite requester, plus immutable boundary/scope context. These are source/canonical identities, not worker-local query/MIR indices. `VisitOrigin.parent/position/requested` remains in the donor's capture: donor records the exact EXTERNAL reference at that original edge before relinquishing the task. The receiver creates its own capture root for the same exact definition and retains source requester metadata. Existing `extraRoots` silently invents Direct/zero-span/no-cleanup roots, so it is not an adequate replacement for a full donated visit.

4. **Fragment coverage is not a second runtime check.** Preserve one complete runtime sweep/coverage and the existing exact unique-module roster. Receiver subwalk records are additional completion fragments, not extra name0/name1 module answers. Feed them to `WalkFragments.mergeOpen` alongside complete module captures before `finiteClosed`, `escapeFree` and global budget validation. Verify each fragment's roots are authorized donated targets; absent/full supplier or inconsistent identity refuses the entire union. `joinFrontier` currently equates record count with module count, so its transport needs an explicit fragment envelope or a premerge stage. Do not weaken exact module/runtime coverage to accommodate it.

5. **Persist every donating consumer's dependencies.** A donated subwalk needs the same separate root recorder/non-MIR input capture as `frontierExtend`. Reuse `frontierExtensionEvidence`, `frontierExtensionReads`, `retainFrontierMirEvidence`, and `frontierNonMirReadsAt` so command7 exports actual receiver query dependencies. The partial fragment is not independently a reusable check. This is required for direct edits and full source-signature invalidation, not just cold proof.

6. **Balance the extension phase without publishing every encountered key.** `frontierComplete` currently broadcasts missing digests; `threadExtend`/`frontierExtend` find only locally remembered keys, so the runtime store remains concentrated. Add a bounded native-only preparation phase: existing owners resolve requested digests to InstanceSeeds and enqueue unique tasks, then all four stores consume that round through the same quiescence engine. This avoids a global seed dictionary for all50k+ keys. Preserve the existing root-recorder/evidence path. Initially steal only unclaimed definitions and keep existing owned definitions pinned: the claim table is an owner map, not a completed-MIR directory. Reassignment of already-owned missing definitions needs an explicit quiescent-round ownership transition and exact owner routing proof; do not silently let receivers skip a claimed task without a full supplier. Measure how many extension roots are eligible before broadening ownership transitions.

7. **Two-pass teardown in the same candidate.** `closeThreadWorkers` currently calls `Worker.close` (signal+join) one worker at a time. Split transport cancellation from joining: cancel all four first, then join all four, then emit the existing marker. Private stores can destruct concurrently, bounded by the original four workers. Preserve public `Worker.close` as cancel+join, RAII cleanup, no payload drop under channel locks, and join-before-any-continuing-fork. This targets the observed0.979s teardown envelope; it does not by itself solve runtime or emission cost.

Suggested ownership: parallel_semantics owns queue/task lifecycle and typed task envelope; worker_forks owns capturedEscapes donation, fragment proof/persistence, and extension round service; interning can audit immutable task metadata and shared-pool lifetime. InstanceKey seed implementation is already validated. Work should begin in a new worktree only after root approves the exact scope.

## Native overlap alternatives

The full prepared-to-joined gap is roughly3.15s in this run, but it is not all removable by merely rearranging joins.

**Small safe handoff:** split `fetchFrontierCache` into final command7 packet collection and later decode/merge/adoption. Collect all owned raw replies, stop/join native workers, then allow existing `NativeCoordinator.start` to fork. Carry the owned packets and exact stamp in ArtifactPreparation; `captureArtifactReplay` consumes them once through the existing validation and produces the exact adopted-root mapping. It must not call `importArtifactCache` again on dead workers or discard the mapping. Parent validation can overlap native compilation. Worker export ends near19.04s; raw collection plus concurrent teardown still precedes fork, so this primarily overlaps the remaining parent merge/adopt work (~1s here), not the entire3.15s. Preserve accept-only publication and discard speculative native outputs if packet/adoption proof fails.

**Larger overlap:** begin private native work as soon as assembled units exist (~17.89s), using an exec-only subprocess boundary or direct async Clang process plan. Existing NativeCoordinator forks and continues Silk compiler execution, which is unsafe while any semantic thread can hold allocator/interner locks. A new path must pre-resolve owned native inputs/flags, stage exact unit bytes, then use the existing prepared fork-to-exec contract; no Semantic/ModuleSources pointers cross. Plain background native compiler threads are not a complete solution because the later detached cache writer also forks. This option needs a dedicated lifecycle design and charges staging/I/O/CPU contention; defer until measured donation and two-pass shutdown results justify the larger scope.

## Required counters and tests

Measure per worker initial/module/runtime/extension elapsed work and idle wait; donated/offered/accepted/refused tasks and bytes; maximum queue/outstanding depth; seed refusals; MIR owned/skipped; Body eligible/refused/published/avoided; distinct completed supplier counts; extension root distribution and rounds; proof merge/cache export CPU; each cancel-to-exit and total join interval. Root timing should record artifact-ready, final worker packet received, all-workers-joined, native-start and final-writer-completed timestamps. Never interpret skipped visits as avoided MIR provider runs.

Focused concurrency tests must cover empty-ready with an active donor, racing last-task completion versus publication, cancellation with idle and active workers, queue saturation/seed refusal keeping local work, and no more than four active consumers. Semantic tests need an actually donated runtime subtree, preserved cleanup/requested-call spans, one runtime roster, missing-supplier refusal, callback/NonParking closure, finite/resource refusal, receiver guard export, and unchanged-caller dependency edits. Extension tests must cover missing keys, duplicate seeds and pinned existing claims. Native gates must retain observing restart, suspension fallback, full diagnostic parity, CPU0 automatic no-pool, and join-before-native/cache-writer. Performance controls remain both same-binary OFF/ON and matching-construction original-source baselines, including direct first/second edits, unchanged and immediate-writer overlap.
