# Shared ordinary body answers: measured opportunity and smallest safe lane

This is a source-only design, not an implementation or speedup claim. Evidence is the single V24 compiler cold build in `benchmarks/v24-cpu-build-3ebpgyqm`, source f5a818088, binary bd36388e. Query identities compare complete bytes including application/profile/module/declaration; a declaration name alone never establishes equivalence.

## What is actually duplicated

Body has 25,498 actual provider starts. Exact supported keys cover 25,483 starts (99.94%): 17,795 unique keys and 7,688 cross-process repeats. Ordinary member-zero Body accounts for 7,650 repeats (21,993 starts / 14,343 keys); selected Body only 38 (3,490 / 3,452). No same-process repeats occurred. This directs the design toward reusable authored typed bodies, not selected generic execution contexts.

Multiplicity is mainly two: 6,931 keys run twice, 298 three times, 51 four times, two five times; 10,513 keys run once. Pointer.fromRef and Lifetime.allAtoms run five times. Semantic.silk contributes 2,243 repeats, Type.silk 379, Mir.silk 360, LlvmCode.silk 248, RegionCheck.silk 195. The largest worker pair is original1/original3 (1,577 shared keys), followed by original0/original1 (1,368). Pair counts overlap for keys with three or more producers and must not be summed as saved executions.

Supported initial worker snapshots contain 19,409 starts and 5,413 repeats: 4,971 repeat instances only among the original four workers, 442 involve a private child. Retained service adds 6,011 supported starts. Of these, 2,275 match a completed exact key in another worker's initial snapshot; 3,736 are new at that boundary. Original workers account for 1,904 boundary-reusable starts, private children for 371. A phase-boundary transfer therefore targets 37.8% of late Body starts but only 29.6% of all Body repeats. It cannot solve most duplicate cold-check work.

MIR and EmissionInputs are different: supported MIR has 50,390 starts / 50,383 keys (seven repeats); supported emission has 40,968 / 40,968 (zero). MIR excludes 48 identity-size starts; emission excludes 37 identity-size and 2,269 output-cap starts. Do not prioritize generic MIR/emission memo sharing based on the much larger count of repeated graph references.

All 205 processes, six semantic workers, expected 13 dumps, process exits, dump intervals, byte/row receipts and cumulative unit identities validated. No event-count overflow occurred. Unsupported exact identities remain explicitly excluded; full exact coverage is not claimed. Parser outputs and exclusions are preserved beside the profile.

## Smallest safe representation

Start with clean completed ordinary Body answers in immutable CLI stores. Preserve the exact scoped key (including current application and selected profile), original Stage (FullyChecked or ContractTyped), typed locals/nodes, relative origins, required bodies, foreign declarations, interface obligations, environment/static iteration data, and the complete provider dependency root. Never reinterpret ContractTyped as a closed runtime proof.

TypedBody already uses body-local node/local indexes and declaration-relative source locations (`TypedBody.silk:737`), which are suitable for a portable capsule. Its signature dependency list (`:588`) contains stable DeclarationIds, but that list is NOT the complete query/source guard. The capsule must also retain the actual provider's dependency DAG: exact observed source selectors/digests, profile/application facts, and demanded query evidence. Use one shared dictionary of stable types/applications/declarations per coarse capsule group and intern decoded values once per receiving worker. Do not repeatedly encode every type inside every node.

The imported body becomes a real local query answer with a local dependency handle referencing the authenticated foreign evidence root. Installation must be transactional: payload, all referenced type/declaration entries and guard mapping first, query publication last. Failed allocation/decode/guard validation leaves the ordinary local provider path available. No source read or cache invalidation dependency may disappear merely because a foreign body is clean. Cache persistence must preserve the adopted dependency root through current Bundle liveness; a raw foreign query-unit index is never usable locally.

Signature answers and immutable resolved body facts can be added to the same capsule when measured useful, with their own exact scoped keys and evidence roots. The current `Value.BodyFacts {index}` points into a mutable, consumable resolver-local table (`Semantic.silk:4259`, `:84676`); sharing this slot number is invalid. Freeze a structural payload and either give each consumer an owned decoded copy or a new immutable accessor. Start with the Body payload and evidence needed to avoid retyping; do not broaden to all query families.

## Two stages, one representation

1. **Build-only, existing barrier:** producers expose a compact directory of completed ordinary Body keys at the initial transport barrier. Before a retained worker starts a missing Body, its source-declaration/module group can be imported from an existing supplier in one batch. No global in-flight query ownership or cycle waiting is needed. Use the existing ancestor/descendant routing to the actual supplier. The measured ceiling is 2,275 avoided provider starts, not all 7,688. This is the lowest-risk end-to-end transport/provenance validation lane, but transfer/decoding can outweigh it.

2. **Cold-check lane:** producers publish completed immutable capsule groups into a bounded shared arena/directory as work finishes. A worker consults this directory only immediately before an ordinary Body provider would run. A ready exact entry can be installed locally; absent/in-flight entries take the normal local path. Do not wait for another in-flight provider initially: cross-worker Body/Signature/BlockSignature dependency cycles need a real distributed cycle rule before blocking can be safe. This completed-only design avoids introducing that rule, at the cost of permitting simultaneous duplicate producers. Current phase snapshots do not reveal how many of the 5,413 initial repeats were concurrent versus completed-before-second-start, so readiness benefit remains unmeasured.

The arena should contain immutable offset-based data or portable capsule bytes, not raw pointers to worker-owned `Shared<T>` values. `Shared` is single-threaded and even read callbacks take exclusive access; `Frozen` refcounts are single-threaded too. `Interned` advertises immutable thread-readable handles, but a post-fork allocation is not mapped into sibling processes, and nested Shared/Frozen fields still need an audit or conversion. Simply swapping fork for threads or copying Shared handles is unsound. A zero-copy shared-address-space typed/type arena is a larger redesign; the coarse portable representation can establish value before taking that on.

## Why this differs from the failed registry

The completed-MIR registry probed repeated escape visits and retained proof captures; it did not hand another worker a ready Body query answer. Much of the expensive typing had already happened before its cut. This proposal probes once at an actual ordinary Body provider miss (~22k observed starts), with a small declaration/context key, and replaces type inference/region checking plus their repeated child work. Shared type/declaration dictionaries amortize transfer across a module/group; there is no socket roundtrip on every MIR edge or query hit. It nevertheless adds real encode/decode/guard costs, which must be counted rather than assumed cheap.

## Acceptance and CPU limit

Require ordinary/selected separation, exact application/profile matches, clean stage preservation, body/header/provider/roster edits, application switch, trivia/span changes, missing/corrupt capsule, failed import followed by retry, forked-child lifetime, and cycle cases. Preserve exact ordered diagnostics and current finite/callback/resource proof; a shared Body is no license to skip runtime closure.

Current perf has an observed Body/BodyFacts/Signature visible-stack union of 6.364 worker CPU seconds, with substantial incomplete unwinds. That is a lower bound on those families, not the total avoidable cost. Counts cannot establish a ten-CPU-second win, and multiplying samples by the repeat ratio is unjustified without cost weighting. The next implementation decision should use that uncertainty explicitly. A body-sharing prototype is now evidence-backed; its performance case still needs a bounded same-binary off/on test including aggregate CPU, transport bytes, peak memory, cold check/build and first edits.
