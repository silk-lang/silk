# Segmented-cache measurement and maintenance contract

Source preparation only. There is no integrated candidate or agreed CLI counter adapter yet. `SILK_CACHE_SEGMENTS` is presence-only: OFF means absent, never `0`. The compiler policy stamp separates OFF/ON namespaces. Mixed live/dead compaction and physical reclamation are not implemented; coarse `CacheRetain.trim`, threshold crossings, published generation counts, and the conservative space-reservation ledger cannot establish a completed maintenance cycle.

`incremental_reporting/cache_segments_sequence.py` owns its exclusive lock. `--comparison source` compares matching-construction V22 against the candidate, requesting ON for both (V22 ignores the flag). `--comparison feature` requires identical binary/source/construction pins and compares absent/OFF to present/ON. Both scrub inherited diagnostics and unrelated prototypes. Commands require explicit pins, CPU lane (`0` or `0,1,2,3`), sequence, operations, and workloads. Use one round initially, exact artifact parity, and original frozen source/stdlib. Run check and build cold→direct first edit→second edit→unchanged; unchanged never primes either edit. Report every positive foreground/settled/total-CPU/writer-CPU delta. After all descendants settle, record allocated and logical storage, deduplicating hardlinks, then clean only that completed mode's generated cache. No timing launch is authorized by this document.

The longer maintenance lane uses `cache_segments_maintenance.py`, with its compiler adapter deliberately unwired until publication/export/maintenance counters exist. The adapter must own the exclusive lock for the whole persistent-cache sequence, pin binary/source/construction, persist raw logs and each stage immediately, make substantive deterministic edits (e.g. distinct observable help strings), and restore source only after every descendant drains. It must not reset the cache between edits. An explicit maximum-edit budget is required; hitting the cap reports `cycle-not-reached`, not success. Do not lower production maintenance thresholds silently. The OFF/V22 comparator replays the exact candidate edit count and final unchanged stage, so amortized cost includes the same work. Record cold→first/second separately from later cycle work.

For this bounded diagnostic, each edit waits for all owned writer descendants before a physical inventory and the next edit. This is intentionally a settled maintenance lane; it does not replace the immediate-edit contention controls. `run_settled` retains foreground, settled, primary/whole-tree CPU, detached-writer CPU, max individual RSS and optional native artifacts through the existing subreaper. A 100ms `statvfs` sampler records observed global filesystem high water; it is a sampled bound, not an exact per-cache peak. Full per-file allocated/logical inventory occurs only after settlement. Exact transient physical peak requires publication-owner evidence; do not label sampled or reserved-byte values exact physical maximum.

The adapter's internal normalized cycle receipts require raw log/record references and generation identities. `mixed-compaction-completed` must show rewritten mixed segments, copied payload bytes, committed output generation and drained writer. `physical-reclamation-completed` must identify retired input generation, retained compacted generation, actual removed objects/allocated bytes, all applicable pins released, and later completion time. Both are required. A refusal or only coarse whole-owner trimming is not a completed cycle. Actual native labels and byte/edge/debt semantics remain to be agreed with the owners; these internal record names are not claims about an existing compiler API.

After the completed cycle, run an unchanged command without rewriting source. Require normal semantic/artifact/native proof, exact diagnostics and artifact/runtime parity against a fresh reference for the identical edited source. Preserve the accepted generation and required-pack evidence. Retained physical storage and publication/compaction/reclamation refusal/debt counters remain in the report even if foreground time improves.

Keep two small correctness controls separate from timing:

- Same directory/source, same candidate: OFF→ON→OFF, each mode executing build→check→build. Capture actual storage-policy stamp/namespace authority and publication status. Compare artifacts/runtime/ordered diagnostics to fresh independent controls. Merely observing success or a changed filename does not prove policy isolation.
- Across build→check→build, record admitted `View.requiredPacks` and exact build-root identities before and after the intervening check. Authenticate needed packs by digest and prove their continued authority/lifetime. The final build must succeed with exact artifact/runtime parity. If it recompiles instead of reusing, report that; artifact parity alone does not prove pack retention or cache reuse.

The source-only helper tests cover presence semantics, clean environments, hardlink accounting, symlink refusal, false cycle evidence, generation binding, bounded stop, and unchanged-after-cycle ordering. No compiler invocation or performance claim is part of these tests.
