# Concurrent structural interner boundary

Source: `.scratch/thread-immutable-prototype`, Types-only commit `7129013afad20af488f5999f61792d7494a773eb`; combined ownership checkpoint `466ff4bf5`. `TypeTable` remains the serial provider. `SharedTypePool` publishes five independent mutex-protected structural sets (Type, Application, DeclarationId, Lifetime, Row). Each `ThreadTypes` owns a separate canonical InstanceKey memo. No worker query result, resolver state or mutable key cache enters the shared pool.

Hashing happens before locking. Type/Application equality can allocate scratch types and encode exact static evidence, so these methods copy at most four immutable candidate handles under lock, release it, compare outside, and reacquire only to compare the candidate-handle snapshot again and publish. A changed same-hash snapshot retries equality; an unrelated insertion does not force retry. Hash equality alone never implies identity. Existing bounded collision policy can miss sharing and is not a promise of universal pointer uniqueness.

Declaration/Lifetime/Row equality only reads immutable components/addresses and has no effect/provider/encoding call, so those comparisons occur under their category lock. An ordinary hit uses one category-lock acquisition. Type/Application misses usually use two, plus rare growth acquisitions; allocation races may retry. No scalability or single-core performance claim has been established.

All storage allocation occurs outside locks. Growth prepares empty replacement buffers, then copies only permanent handles and stored numeric hashes under the lock with `appendWithinCapacity`; displaced buffers are dropped after unlocking. Publication itself is pure and cannot fail halfway through the paired handle/hash/slot update. `InternCandidate<T>` owns an unpublished permanent allocation and discards it if it loses a race or unwinds through an allocation failure. Successful publication immediately disarms that unique owner before any further effect call. No shared handle can be reclaimed by this owner.

Focused source fixtures cover stale candidate-snapshot rejection, exactly-once destruction of a racing unpublished allocation, 32 forced equal-hash/different lifetime-binder identities across table growth, shared Type/Application handles, distinct binder identities, and worker-local canonical memos. The parent's separate native-thread fixture produces two real Semantic bodies with the same shared type pool. All thread-transfer bounds are derived through Published/Arc and Interned's conditional leaf contract; this file adds no unchecked Concurrent/Transferable implementation.
