**1. Blocking: normalization omits a distinct policy input, `Carry.direct`.**

Design 115, 198–235 and 438–439 specify normalization by value port/definition, physical component, leaf and real/shadow/inherited role. They retain paired definition/read witnesses and mapping precision, but never specify directness or its merge/transfer rules. This is not derivable merely from Exact precision, field identity, or leaf identity.

Actual code establishes the distinction:

- `Carry.direct` means the position still contains the loan's own reference (BC 439–444).
- A fresh borrow has direct=true (2050). Aggregate placement and matched forwarding preserve it (2720–2728). `declaredResultCarries` places a source at an exact field but explicitly sets direct=false (2405–2426); that same declared branch can retain Exact precision (2572–2573).
- `sameHoldingPosition` deliberately distinguishes direct and indirect carries even with the same loan and field (5366–5375).
- Directness controls call-retention narrowing (`keptSink`, 8066–8067; `narrowSlots`, 8165–8197), source-slot eligibility (3408–3412), destination eligibility (3471–3484) and exact destination placement (3440–3445).

Small operation example: create L, then deliver L at aggregate field 0 either by ordinary aggregate placement or by authenticated declared-call placement. Both can be Exact and have the same receiving component/leaf/role, with different paired witnesses. The first route is direct; the second is not. At a consumer with own=false, a locally typed L, whole=Universal, and a compatible precise view slot classified Local, direct=true produces Local while direct=false produces Unknown. This is exactly the `keptSink` branch boundary; no compiled Silk outcome is asserted. An aggregate with separately classified reference slots is the relevant shape, not a bare reference whose outer-region identity already makes `own` true.

Merging those routes and taking any positive Direct witness can incorrectly remove a storing effect. Dropping directness everywhere loses supported narrowing on genuinely direct-only values. Treating every directness witness as a second physical component can instead corrupt the normalized multiplicity/complete guards. These choices cannot be left implicit.

**Required amendment:** preserve directness and placement evidence conditionally with each paired route witness, define its quantifier at each consumer, and define how a single normalized physical occurrence combines possible policy outcomes. Retain exact source/read pairing for `excludedTransferRead` (3489–3506); a direct witness from one definition cannot authenticate another definition's read/slot. Specify how historical alternative witnesses avoid becoming extra precision observations while genuinely distinct components remain separate. Demonstrate aggregate-vs-declared-call, direct-only and indirect-only controls at the operation-model level.

Also make EffectId target identity explicit. The printed key at design 117 contains EvalId/phase/physical operand-component/kind, but two distinct leaf alternatives L and M at the same component can require different precision/whole-hold/unretained effects. Either include the target leaf/loan (and any distinct output placement) or define payload-indexed effect facts under an occurrence ID. A scalar effect keyed only as printed is not injective. This is a small finite correction, not evidence of an exponential domain.

**2. Blocking: the precision lattice is specified, but its grounded normal-rule translation is not.**

Design 244–269 adds transported-quality joins to the structurally versioned loan-global state. This is a substantive new cyclic dependency. Design 306–324 promises explicit precision tables and grounded Exact, while 366–370 offers a grounded identity loop. The supplied model establishes the latter only for source membership (`entry -> p -> q -> p`, model.py 215–218); it has no transported-quality join or observation-state circuit.

The missing choice is observable on the proposal's own smallest positive:

```
q = Borrow(O)                  // grounded Exact
while condition {
    q = identityNamingO(q)     // one occurrence, unique-name retention, no loss
}
```

With the new input barrier, let I be loop-input quality and T the transported backedge quality. Their equations are `I = join(Exact,T)` and `T = I`. All four quality categories are algebraic fixed points, but a real execution with no loss-producing operation stays Exact. Unsupported loss must not support itself.

A literal one-hot translation of the finite join/identity table has, for each Q:

```
InputQuality(Q) <- EntryExact, BackedgeQuality(Q)
BackedgeQuality(Q) <- InputQuality(Q)
```

Even with independently grounded source membership, the least positive closure derives no quality category. Alternation is total on those atoms, but all four are false. It has not proved Exact; the category invariant makes this unusable/inconsistent, so the promised positive is lost. Simply seeding InputExact independently of every incoming quality is also wrong when a real backedge store supplies Stored.

The independent probe in `probes.py` demonstrates this distinction. It does **not** claim the author implemented this failing encoding; no encoding is implemented. It shows why a valid generic Gamma theorem plus the instruction “explicit tables” does not settle the compiler translation.

**Recommended principled correction:** define Stored-loss and Alternatives-loss bits with grounded positive generation/transport, and derive Exact only for a genuinely present source when both possible loss bits are false. Keep undefined loss distinct from false loss. The probe's limited loss-bit encoding grounds Exact for the identity loop and propagates a real backedge Stored loss to the earlier loop consumer. The full amendment must specify the rules for absence, uncertain presence, per-source versus per-loan versions, snapshot joins and each original result/store/cleanup transition, including complete/drop feedback. This remains one rule system; it does not require a second flow engine or “initial Exact for all candidates.”

Define the temporal contract explicitly as well: transported loss may reach a lexically earlier observation only through an actual value/read backedge. It must not reach a saved pre-loop copy merely because the loan ID is equal. The retained global structural version chain can still affect later observations as the original policy requires. Repeated real same-loan occurrences must see sequential effects after the single operation-wide snapshot. Validate these distinctions with model cases before claiming this new join ready to implement. Native precision acceptance remains a later obligation.

**3. Blocking: the finite component construction needs an explicit Semantic preparation input/API amendment.**

The route-graph direction at design 133–194 is appropriate: residual routes can be cyclic; external selector IDs do not imply separate owners; all alternatives must be checked. But the proposed construction assumes inputs that the current boundary does not supply.

Design 136–140 and 175–180 require typed inline field/member descriptors before source selection; 150–154 requires original declaration/result/capture/kept-slot routes up front. In the real compiler, `Type.Nominal` stores declaration identity and arguments, not its member types (`Type.silk` 120–128). `Types` only exposes type interning (`Types.silk` 13–16). `TypedBody.Field.declared` supplies a selected authored field, not a complete shape for an unprojected nominal entry/result (`TypedBody.silk` 136–139). Complete member shapes require Semantic's dependency-tracked `Family.MemberShape` demands (`Semantic.silk` 54926–54957). Declared result routing similarly demands original signature bounds and stored member types (51389–51506).

The original API declaration's `prepare` (public-api.silk.txt 37–41) accepts owner/locals/nodes/obligations/premises/cleanup and only Allocator/Types capabilities. It has neither a resolver/query owner/dependency collector nor prepared component descriptors. This proposal amends the returned selection but supplies no new preparation input or provider contract. It cannot literally build the specified nominal component inventory through the existing boundary. For example an external `Entry` of `Pair<T>` passed/stored whole has nominal identity and arguments without an authored Field node enumerating its members. Deciding to use a sparse symbolic root instead is a possible alternative design, but it must specify the required maps for later selection, whole copies, result placement and field kills rather than assume those descriptions already exist.

The archived environment WIP corroborates the missing integration seam, not its solution. Its original Signature and AppliedOperation routing demands are in Semantic (WIP 29869–29936), after `prepare` (29947). It returns Pending for non-Field residual steps (30020–30028), and separately handles Effect-success selections through the selected original signature (29919–29935). Replacing Vector with SourceRouteId alone neither moves necessary queries before construction nor defines that product's state/transitions.

**Required amendment:** give a concrete declaration-level contract for a finite, immutable component/contract descriptor package prepared through Semantic's tracked queries (analogous in ownership to `borrowCleanup`, Semantic 62716–62796), or an explicit query provider with dependency ownership. State which evidence is available before graph reservation, which semantic obligations remain after solving, and why there is no solve -> new component -> re-solve cycle. Define SourceRouteId access, analysis-instance ownership/stamp, endpoint/type/application evidence, acceptance ports, supported selector kinds including member/index/referent and Semantic's success channels, and the product's visited-state/proof rule. A repeated route vertex must not itself prove a Contents/outlives obligation. Preserve the original Signature/AppliedOperation owner and substitutions rather than coalesced caller types.

Then work through at least one nominal copy + exact field overwrite, one recursive external selector route, and one original-contract result/success route with distinct sibling binders. Show where all IDs/edge maps come from and which query owns each dependency. No native implementation is requested for this amendment. Do not convert a currently supported selector to UnknownSelection merely because the descriptor contract is missing.

**Mathematical enclosure and cost assessment.**

For a fixed finite ground normal program, Gamma as defined at design 328–334 is antitone; its reduct has a least positive model. Starting with empty K and universal U yields growing K and shrinking U. Every stable model is enclosed, positive ungrounded cycles disappear, and a globally total well-founded result is the unique stable model. The complete/drop example correctly has two solutions; the refiner leaves the four output atoms undefined rather than choosing one or the invalid frozen cross-output. The generic model agrees. None of this proves that compiler executions/certificates correspond to the chosen rule program.

AllExact via `not BadExact` is acceptable only with the independent positive witness/outer gates, complete candidate coverage, and correctly grounded precision. A possible witness in U is not a witness in K. A total truth assignment also needs the compiler's category/coverage invariants; “all precision categories false” is not a valid quality. No-stable-model cases cannot be used vacuously, and undefined mandatory effects/requests must block Checked. The two-atom model checks that total enclosures are unique stable interpretations, but does not execute a compiler Checked-admission function or implement inconsistency detection. A total reachable proof slice can be useful with unrelated undefined atoms; every mandatory dependency must actually be included in that slice.

O(A*(A+R)) is a meaningful conservative bound for the proposed indexed alternating solver, where R counts ground rule-body incidences (and rule/head storage is accounted for). Fixed-domain AND/OR/negative literals, the MAX-sensitive finite naming machine, >=2 via pairs, and finite parent reachability need not enumerate subsets. Multi-input quality joins can be factored; no exponential table is necessary. The supplied Python closure scans are not the proposed indexed implementation and do not measure this bound. The polynomial component/fact bounds are conditional on the explicit finite descriptor construction and typed product state. Finding 3 leaves those inputs unspecified; no source-size/generic-expansion bound or practical memory/time result follows. No hidden exponential mechanism was demonstrated in the finite guard algebra itself.

The following critical boundaries were traced against production source, not inferred solely from the normal-program theorem:

- Projection/aliases: `readPath`, `exactPath`, `discards`, `prefixedPath`, `pathContains` (857–958), `attributeRead`/`disjointFields` (1526–1566), `referencedPath` (1635–1647), and `destinationField` (3438–3465) impose different predicates. Computed index writes do not kill an entire remainder class; reference/unknown boundaries do not acquire field disjointness. Local physical storage and a value-definition snapshot must remain distinct so a referent read observes the right storage definition.
- Result policy: the gate table matches retainedParents' `known && !stores && count>1` (2673), declared-source pre-loop sampling, required-source conditional closure (590–632), MAX naming (2691–2709), outside/declared/complete/unique/implied precedence (2535–2609), and declared placement independent of the earlier exact branch. Operation-wide snapshots must remain stable while repeated-ID per-occurrence versions advance. `unreachableField` retains the nonempty earlier-whole-hold condition and every relevant described/known hold (1592–1629).
- Call/capture state: invoke evaluates pipeline input, callee and remaining arguments in that order, then finish/storeIntoLent/storeThroughExclusive (3727–3768). Defer applies retention immediately after each argument visit (3776–3803). Construct's opaque escape pass precedes universal stored-region/CaptureHold handling, and `ownedStorageLoan` reads precision during construction (3595–3713). These effects cannot all be delayed semantically to the final loan snapshot just because materialization occurs once.
- Conditional definitions: storeIntoLent (3269–3349) and storeThroughExclusive (3536–3586) conditionally rehold existing plus received values. They are possible call writes, not unconditional strong kills of all previous sources. PlaceAssignment retains exact-path kill/shadow and precision effects, plus the existing through-reference refusal (4682–4761); Displace retains its unsupported local retained-value boundary (4767–4818). - Cleanup/control flow: observeCleanup (4366–4424), releaseScopes (4290–4350), replace-before-write cleanup, loopCleanup's open-loop test in hold, guard/binder effects, never/return/break/continue and While (4887–4935) are actual semantic dependencies. Existing shadow/inherited history remains relevant to its distinct type/liveness consumers, but cannot masquerade as a currently stored value source. No unpublished literal-loop feasibility change was assumed.
- Structural completeness versus checker stop: `visitNode` currently stops at `walker.outside` (4488), and several store/cleanup paths return early. Design 94–104 correctly requires continued structural reservation. C must distinguish this analysis stop from runtime noncompletion. In `q=caller; while (...) { store(q); q=Borrow(L) }`, gating the later source/CFG edge on `!outside` and deriving outside from that source makes an artificial negative cycle. Reservation plus an explicit coverage failure must preserve the later runtime source; it must not erase the reason for the failure. Show the generated rules for this case, rather than blindly copying every walker.outside gate as a CFG predicate.
- Final admission/order: current check prioritizes guard consumption, non-return lifetime refutation, outside refusal, then event conflicts/reports, storing, imprecision, inherited status and region closure (6094–6121, 6166–6174, 6366–6395). The full structural scan may discover a later exact conflict after an earlier unsupported site. The implementation must define applicability and preserve required diagnostic precedence; sorting all new effects by source location alone is insufficient. Incomplete analysis or foreign/missing/duplicate/recovery request outcomes must never bypass region or ownership checks.

These observations support the broad architecture, but the inventory of sites is not a completed translation.
