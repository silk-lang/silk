A `[profiles.release]` or `[profiles.dev]` table keeps the built-in profile's `optimization` and `debug` where it sets neither, so `[profiles.release]` with only `codegen-units = 16` stays optimized without debug information.

## Migration

A `[profiles.release]` table that sets no `optimization` was built unoptimized with debug information; it is now optimized without it. Add `optimization = "none"` and `debug = true` to keep the old build. A `[profiles.release]` table that sets `optimization = "speed"` but no `debug` loses its debug information; add `debug = true` to keep it.
