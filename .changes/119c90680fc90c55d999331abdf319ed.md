`silk check` reports SEM0192 when a package declares an `extern "C"` function with different C types than a standard-library declaration of the same symbol in a module it imports, instead of leaving it to the build.

## Migration

A package whose `extern "C"` declaration disagrees with the standard library's now fails `silk check`. Change the declaration to the C types the note's standard-library declaration uses, for example `unsafe extern "C" fn close(fd: i32) -> i32`.
