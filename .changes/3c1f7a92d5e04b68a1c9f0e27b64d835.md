`silk check` reports SEM0192 for two declarations of one C symbol in the package that differ, whether or not they are called, instead of leaving it to `silk build`.

## Migration

Two `extern "C"` declarations of one symbol in a package that were accepted because nothing called one of them are now rejected. Give both the same C parameter and result types and the same `@foreign` contract, delete the unused one, or put each system's variant in its own `static if` arm.
