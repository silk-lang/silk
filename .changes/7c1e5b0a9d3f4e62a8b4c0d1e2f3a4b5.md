Make `silk.compress.deflate` write the same bytes as zlib 1.3.1 and consume and write per step what zlib's `deflate` does, and give `silk.compress.inflate` zlib's failure causes (`Decoder.failureDetail`), window bits (`Decoder.setWindowBits`), a stop at the end of a gzip member (`Decoder.setMemberStop`) and at each block (`Decoder.setBlockStop`); `Encoder.setGzipSystem` sets the gzip operating system byte. `Options.hash` chooses `Hash.Rolling` (zlib 1.3.1's bytes, the default of `Options.make`) or `Hash.Multiplicative`, the hash of Chromium's zlib, which writes the bytes of Node.js and Chrome and is faster.

## Migration

- Compressed bytes change wherever they differed from zlib's: level 0 always, other levels with dictionaries, parameter changes, or flushes into a full output. Regenerate stored digests of `Encoder` output.
- `Encoder.setParameters` ends the current block only when the strategy or the kind of level (0, 1 to 3, 4 to 9) changes; code that relied on a block boundary at every call must flush with `Flush.Block` itself.
- A `Flush.Sync` or `Flush.Full` whose output fills can write its marker again on the next step, as zlib does; give the step more than 6 bytes of output to avoid it.
- `Options` has a new field, `hash`: struct literals of `Options` must add `hash: Hash.Rolling` to keep their bytes. `Options.make` is unchanged.
