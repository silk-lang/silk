Silk code can call an `export "C"` function directly (inside `unsafe`); the build used to stop with `unsupported[foreign-export]`. SEM0082 names the unsafe operation and the fix, such as "`qsort(...)` is unsafe; write `unsafe qsort(...)`, or put it in an `unsafe { }` block". A C function-pointer parameter missing from `with Intrinsic.foreign(callbacks: ...)` is now SEM0187 showing the clause to add, instead of `unsupported[ForeignCallback]`. Passing a Silk fn for a C function pointer, a `bool` C static, and assigning a C static now say what is wrong.
