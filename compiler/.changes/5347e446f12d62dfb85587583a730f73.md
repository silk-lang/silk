Two stack intrinsics and a `silk.stack` module that wraps them:

- `Intrinsic.frameAddress() -> [*]const u8` returns the address of the running function's stack frame. It is safe and lowers to `llvm.frameaddress`; on `wasm32` it is the frame in the linear-memory stack.
- `Intrinsic.stackAllocate<T>(count: usize) -> [*]mut T` is unsafe and returns uninitialized, naturally aligned stack storage that lives until the running function returns. A byte count that does not fit `usize` traps with `arithmetic overflow`.
- `Stack.frameAddress()` and `Stack.withStorage<T, A>(count, use)`, which passes the storage to a callback and releases it when the callback returns.
