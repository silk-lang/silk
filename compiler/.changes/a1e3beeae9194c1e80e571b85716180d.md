Integer arithmetic that traps every time it runs is now a compile-time error, so `silk check` finds it instead of the program stopping at run time. Integer `/` or `%` by the constant zero reports SEM0248, as in `1 / 0` or `count % 0`. Arithmetic whose operands are all constants and whose result does not fit its type reports SEM0247 with the value and the range, as `2147483647 + 1 is 2147483648, outside the i32 range, -2147483648 through 2147483647, so it always traps`. Constant operands are literals, toolchain and other packages' constants such as `i32.MAX`, and arithmetic over those. A constant declared in the same package, and any local binding, still traps at run time. To stop a program on purpose, write `Intrinsic.trap("reason")` instead of `1 / 0`.
