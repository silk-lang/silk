Messages about another package's code are clearer:

- A type from another package is named with that package's name, `geo.lib.Square` instead of `lib.Square`, in diagnostics, in `unhandled error:` reports and in their call paths.
- SEM0083 for an impl outside the allowed modules states the rule and the modules, for example "`geo.lib.Shape` is declared in `geo.lib` and `i64` is a builtin type, so this impl must be in `geo.lib`".
- An error in a library's generic body is reported once, at its own site, rather than again at the program's call.
- A workspace member skipped for a missing root module, whose source root has `lib.silk`, gets a hint to set `kind = "library"` and `exports`.
- SEM0030 names both types: "This element is main.Tri, but the array holds main.Circle".
